# 💬 Go WebSocket Chat API

## 1. Описание Проекта и Выбор Архитектуры

Асинхронный WebSocket-сервис для многопользовательского чата, разработанный на **Go** (Fiber). Сервис использует **Redis Streams** для обеспечения масштабируемой и надежной рассылки сообщений между всеми запущенными инстансами приложения.

### Redis Streams vs. Apache Kafka

Для данного проекта был выбран **Redis Streams** по следующим ключевым причинам, несмотря на популярность Kafka:

1.  **Инфраструктурная Простота:** Redis уже используется в проекте. Использование Redis Streams исключает необходимость развертывания, настройки и обслуживания отдельного кластера Kafka, значительно упрощая инфраструктуру.
2.  **Низкая Задержка (Latency):** Для чат-приложений критически важна минимальная задержка. Redis обеспечивает сверхбыструю доставку сообщений, идеально подходящую для реального времени.
3.  **Идеально для Go:** Модель **Consumer Group** в Redis Streams естественно интегрируется с горутинами, позволяя каждому инстансу `Hub` эффективно потреблять сообщения и легко масштабироваться.

## 2. Установка Необходимых Инструментов

Для запуска и тестирования проекта мы будем использовать утилиту **`make`** как центральный командный интерфейс.

### Установка `make` (Для Debian/Ubuntu)

Если у вас нет утилиты `make`, установите её с помощью следующей команды:

```bash
sudo apt update
sudo apt install make build-essential
````


## 3\. Запуск Проекта (Local Development)

### 3.1. Подготовка и Зависимости

Используйте команды `make` для настройки рабочего пространства:
1. используйте temp.env.template чтобы создать свой .env и закинуть его в корень директории проекта
2.  **Генерация Моков (обязательный шаг для тестов):**
    ```bash
    make generate
    ```
3.  **Запуск:**
    ```bash
    make run #make stop - для остановки
    ```

## 4\. Тестирование и Примеры Запросов

Для тестирования WebSocket-соединений рекомендуется использовать **Postman** (вкладка "WebSocket") или аналогичный инструмент.

### 4.1. Тестирование WebSocket-соединений

#### Шаг 1: Подключение Клиента A

Откройте два новых WS-соединений в Postman.

  * **Протокол:** `ws://`
  * **URL:** `ws://localhost:8080/Alice`

    * **Протокол:** `ws://`
  * **URL:** `ws://localhost:8080/Bob`

#### Шаг 2: Отправка Сообщения (Broadcast)

Отправьте через соединение Alice сообщение Bob.

  * **Действие:** **Broadcast**
  * **Тело (JSON):**

<!-- end list -->


```json
{
    "from_id": "Alice",
    "to_id": "Bob", 
    "content": "Привет! Я только что подключилась."
}
```


**Результат:** bob получит это сообщение.


#### Шаг 3: Тестирование Юнит-тестами

```bash
# Сначала генерируем моки, затем запускаем тесты

```
